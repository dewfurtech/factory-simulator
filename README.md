# Factory Simulator

เครื่องมือวางเลย์เอาท์สำหรับส่งให้ลูกค้าดูก่อนซื้อเครื่อง: รับแปลนของลูกค้ามา วาดห้องทับ วางเครื่อง Mastrox ตามขนาดจริง
แล้วส่งลิงก์ให้ลูกค้าลองย้ายเครื่องเองและส่งกลับ ดูได้ทั้งแปลน 2D และ 3D แบบเรียบ (เครื่องเป็นก้อนเหลี่ยม ๆ ขนาดจริงที่ยังเห็นโครงและสีของรุ่น มีชื่อกำกับ กดดูรูปเครื่องจริงได้)
ไม่มีแอนิเมชัน ไม่มีโหมดสมจริง: โปรแกรมตอบคำถามว่า "วางได้ไหม วางอย่างไร ของเข้า-ออกทางไหน" เท่านั้น

## เริ่มใช้งาน

```bash
npm install
npm run dev        # เปิด http://localhost:5174
npm run build      # ตรวจ type แล้ว build ลง dist/
npm run typecheck  # ตรวจ type อย่างเดียว
npm test           # เทสต์โค้ดเรขาคณิตใน src/model ด้วย Vitest
npm run test:e2e   # Playwright smoke test ของไหลงานหลักในเบราว์เซอร์ (ครั้งแรก: npx playwright install chromium)
npm run lint       # ESLint (typescript-eslint + react-hooks)
npm run format     # จัดรูปแบบโค้ดทั้งโปรเจกต์ด้วย Prettier
```

ต้องใช้ Node 20 ขึ้นไป โปรเจกต์บันทึกใน IndexedDB ของเบราว์เซอร์ และส่งออก/นำเข้าเป็นไฟล์ `.factory.json` ได้จากหน้ารายการโปรเจกต์หรือเมนูหลักในหน้าแก้ไข เมนูเดียวกันบันทึกแปลนทั้งผืนเป็นรูป PNG หรือไฟล์ SVG ได้ (ตามที่เห็นในจอ ณ ซูมนั้น ไม่มีเส้นกริดและเครื่องหมายแก้ไข)

## หน้ารายการโปรเจกต์

- **อัปโหลดแปลนของลูกค้า** (PDF / รูป) คือทางหลัก กล่องใหญ่บนสุด ลากไฟล์มาวางหรือคลิก ปุ่มนำเข้าไฟล์และสำรองทั้งหมดอยู่ที่หัวข้อ "โรงงานของฉัน" (เมื่อเปิดโหมดตกแต่งภายในอยู่ หัวข้อเป็น "โปรเจกต์ของฉัน" และช่องค้นหาเป็น "ค้นหาชื่อโปรเจกต์หรือลูกค้า")
- ใต้กล่อง: **ผังเปล่า**, **ห้องตกแต่งภายใน** (ดูหัวข้อ "โปรเจกต์ตกแต่งภายใน") และเทมเพลตเล็ก ๆ สองอัน (โรงงานตัวอย่าง, Layout Mastrox)
- เปลี่ยนชื่อ ทำสำเนา ส่งออก ลบ และนำเข้าไฟล์ `.factory.json`
- **สำรองทั้งหมด**: รวมทุกโปรเจกต์พร้อมภาพแปลนเป็นไฟล์เดียว (`factory-backup-<วันที่>.json`) นำเข้ากลับได้จากปุ่มเดียวกับไฟล์โปรเจกต์ ข้อมูลอยู่ใน IndexedDB ของเบราว์เซอร์เท่านั้น แอปขอ persistent storage จากเบราว์เซอร์ให้ แต่ยังควรสำรองเป็นไฟล์

## หน้าแก้ไข

แปลนใหม่มีการ์ดนำทาง 3 ขั้นด้านบน: **วาดอาคาร → วางเครื่อง → แชร์ให้ลูกค้า** คลิกแต่ละขั้นเพื่อเปิดเครื่องมือนั้น ขั้นที่ทำแล้วมีเครื่องหมายถูก การ์ดหายไปเองเมื่อมีผนังและเครื่องแล้ว (กด × ปิดได้) ปุ่ม **แชร์ลิงก์** บนแถบบนเป็นสีส้ม

**ชื่อโปรเจกต์และลูกค้า**: คลิกชื่อที่มุมซ้ายบนเพื่อแก้ชื่อ และใส่บริษัทลูกค้า ผู้ติดต่อ เบอร์โทร หมายเหตุ บันทึกเมื่อปิดแผง (Ctrl+Z ย้อนได้ทีเดียว) ชื่อบริษัทขึ้นข้างชื่อโปรเจกต์และบนการ์ดในหน้าแรก ค้นหาจากชื่อลูกค้าได้ ข้อมูลลูกค้าไม่ไปกับลิงก์แชร์

**เครื่องมือ (แถบซ้าย)** แบ่งเป็นสามกลุ่มตามลำดับงาน: **อาคาร** (ผนัง ห้อง ประตู เสา) · **จัดวาง** (เครื่อง เป็นสีส้ม, พื้นที่, ทางเดิน) · **ดู** (วัด ภาพแปลน) กริดบนแปลนแสดงเฉพาะตอนถือเครื่องมือวาด

- **ผนัง**: ผนังทึบ, ผนังกระจก พิมพ์ความยาวแล้ว Enter ได้ขณะวาด
- **ห้อง / โซน**: ห้องสี่เหลี่ยม (คลิก 2 มุม) แต่ละห้องกำหนดประเภทโซนได้ (ไลน์ผลิต, คลัง, สำนักงาน, โรงอาหาร ฯลฯ) ซึ่งกำหนดสีพื้น ห้องที่ไม่ใช่สี่เหลี่ยมวาดด้วยผนังทีละด้าน
- **พื้นที่**: กล่องโปร่งแสงไม่มีผนัง วาดเป็นกรอบหรือทีละจุด ใช้ตีเส้นโซนงานหรือวาดทับแปลน
- **ประตู / หน้าต่าง**: ประตูเดี่ยว ประตูคู่ ประตูม้วน ประตูเลื่อน หน้าต่าง ช่องเปิด ดับเบิลคลิกผนังเพื่อเพิ่มประตูได้ตรง ๆ กด `G` สลับด้านบานพับ `F` สลับด้านเปิด
- **เสา**: เสาเหลี่ยม เสากลม หรือ **ตารางเสา** (ลากกรอบแล้ววางเสาทุกระยะที่ตั้ง ค่าเริ่มต้น 8 ม.)
- **ทางเดิน / ทิศทางงาน**: ตีเส้นทางเดินคน (กว้าง 1.2 ม.) ทางรถโฟล์คลิฟท์ (กว้าง 3 ม.) หรือ **ลูกศรทิศทางงาน** (วัตถุดิบเข้า → ผลิต → ส่งออก ลูกศรชี้ไปทางจุดสุดท้ายที่คลิก) คลิกวางจุดตามแนวกลางทาง พิมพ์ความยาวแล้ว Enter ได้ จบเส้นด้วย Enter, ดับเบิลคลิก หรือคลิกจุดเดิม ความกว้างแก้ได้ที่แผงขวา ของที่วางทับทางเดินจะขึ้นในปัญหาการวาง (ลูกศรไม่กีดขวางอะไร)
- **วัด**: สายวัดระยะ คลิก 2 จุด วัดต่อได้หลายเส้นพร้อมกัน (เส้นที่วัดไว้บันทึกไปกับโปรเจกต์และติดไปกับลิงก์แชร์ ลูกค้าเห็นและวัดเพิ่มได้ ลบด้วย Ctrl+Z, Backspace หรือ "ล้างทั้งหมด" ที่มุมขวาล่าง) ดูดเข้าหามุม ผนัง และขอบเครื่อง/เสา แสดงระยะตรงพร้อมระยะแนวนอน-แนวตั้ง `Shift` ล็อกแนวตรง `Backspace` ลบเส้นล่าสุด `Esc` ยกเลิก
- **เครื่อง**: เปิดคลังเครื่องจักรและอุปกรณ์

**คลังเครื่องจักรและอุปกรณ์**

- แท็บ Mastrox: เครื่องทุกรุ่น แยกตามหมวด (ปิดขอบ, CNC เจาะ, เครื่องเสริม) การ์ดแสดงรูปเครื่องจริง บางรุ่นมีอุปกรณ์เสริมให้ติ๊กเลือก เช่น Rakete 3500A เลือกโต๊ะยกและสายพานได้ แล้วพื้นที่บนผังยาวขึ้นตาม
- แท็บอุปกรณ์โรงงาน: สำนักงาน, ผลิต, จัดเก็บ, พนักงาน, อื่น ๆ (โต๊ะ, ชั้นวางพาเลท, โฟล์คลิฟท์, ล็อกเกอร์, บันได, พื้นชั้นลอย, ราวกันตก ฯลฯ)
- แท็บของฉัน: เครื่องที่ลูกค้ามีอยู่แล้วหรือของที่ไม่อยู่ในคลัง กด "เพิ่มโมเดล" ตั้งชื่อ ขนาด สี รูปทรง (กล่อง/ทรงกระบอก) และ tag กรอง tag ได้จาก chip ค้นหาจากชื่อหรือ tag ได้ แก้ไข/ลบจากไอคอนดินสอบนการ์ด เก็บในเบราว์เซอร์ และติดไปกับไฟล์ส่งออกของโปรเจกต์ที่ใช้มัน
- คลิกแล้ววาง หรือลากไปวางบนแปลน ด้านที่มีขีดหนาคือด้านหน้าเครื่อง กด `R` หมุน, `Ctrl+D` ทำสำเนา
- เครื่อง Mastrox มี**ลูกศรงานเข้า (แดง) / งานออก (น้ำเงิน)** ข้างตัวเครื่องทั้งบนแปลนและใน 3D: เครื่องปิดขอบและไลน์ Rakete ป้อนทะลุจากปลายหนึ่งไปอีกปลาย เครื่องเจาะ เลื่อย อัด เข้า-ออกฝั่งคนยืน (ด้าน `flow` ใน `src/machines/data.js` อุปกรณ์เสริมของ Rakete ย้ายปลายให้เอง) แผงรายละเอียดบอกด้านเป็นคำ
- วางกล่องเปล่าไว้ก่อน แล้วค่อยเลือกรุ่นเครื่องจากแผงรายละเอียดภายหลังได้ แอปจะเสนอรุ่นที่ขนาดใกล้เคียงให้ก่อน

**แผงด้านขวา**

- **รายละเอียด**: แก้ชื่อ ขนาด ประเภทโซน ความกว้างประตู ฯลฯ ของสิ่งที่เลือก คลิกที่ว่างเพื่อตั้งค่าโรงงาน เครื่อง Mastrox แสดงรูปเครื่องจริง (คลิกเพื่อขยาย) ประเภท และขนาด ยาว × ลึก × สูง ตามโบรชัวร์ รุ่นที่ยังไม่มีรูปใช้รูปรุ่นใกล้เคียงและบอกไว้ ไม่แสดงราคาหรือสเปก
- **ปัญหาการวาง**: แจ้งเครื่องที่ทับกัน ชนผนัง สูงเกินฝ้า หรือกินพื้นที่คนยืนทำงาน คลิกเพื่อกระโดดไปดู
- **เลเยอร์**: รายการห้อง พื้นที่ ผนัง ประตู เสา เครื่องจักร อุปกรณ์ ซ่อน/ล็อกทีละชิ้นหรือทั้งกลุ่ม ดับเบิลคลิกเพื่อไปดู

**วิธีใช้**: ปุ่ม **?** เหนือปุ่มซูม (และมุมขวาล่างของหน้า 3D) เปิดวิธีใช้ของเครื่องมือที่ถืออยู่กับคีย์ลัดทั่วไป ไม่มีแถบคำแนะนำค้างบนจอ

**คีย์ลัด**: `Ctrl+Z` / `Ctrl+Y` เลิกทำ-ทำซ้ำ, `Delete` ลบ, `Esc` ยกเลิกเครื่องมือหรือการเลือก, กดค้าง `\` เพื่อดูแปลนใต้ภาพวาด

**มือถือ**: แถบเครื่องมือย้ายลงไปเป็นแถวเลื่อนได้ด้านล่างจอ เมนูย่อยเปิดขึ้นด้านบน

**จอสัมผัส**: นิ้วเดียวทำงานเหมือนเมาส์ (แตะเลือก ลากย้าย วาด) สองนิ้วเลื่อนและซูมแปลน 2D ส่วน 3D ลากนิ้วเดียวหมุน สองนิ้วเลื่อน/ซูม

## โปรเจกต์ตกแต่งภายใน

> ยังไม่เปิดให้ลูกค้า: บนเว็บจริงปุ่ม **ห้องตกแต่งภายใน** ซ่อนอยู่ เปิดเว็บด้วย `?interior` (เช่น `https://<โดเมน>/?interior`) ครั้งเดียว ปุ่มจะขึ้นในเบราว์เซอร์นั้นตลอด `?interior=0` ซ่อนกลับ `npm run dev` แสดงเสมอ โปรเจกต์ตกแต่งภายในที่สร้างแล้วเปิดได้ตามปกติ (`src/interior/flag.ts`)

ปุ่ม **ห้องตกแต่งภายใน** ในหน้ารายการสร้างโปรเจกต์อีกชนิด (`kind: 'interior'`) การ์ดของมันมีป้าย "ตกแต่งภายใน" เปิดด้วยลิงก์ `#/p/<id>` เดิม แต่ได้หน้าแก้ไขของตัวเอง (`src/interior/InteriorEditor.tsx`) ที่ประกอบจากชิ้นเดิมของแอป โปรเจกต์โรงงานไม่เปลี่ยนอะไร ไฟล์ `.factory.json` เก่าไม่มี `kind` จึงเปิดเป็นโรงงานเหมือนเดิม

**ห้องตัวอย่าง (คอนโด)** ในแถวเทมเพลตของหน้ารายการ (เห็นเมื่อเปิดโหมดนี้) สร้างคอนโด 1 ห้องนอน 7.0 × 5.5 ม. ที่ตกแต่งครบ: นั่งเล่นรวมครัวและมุมทานข้าว ห้องนอน ห้องน้ำ วัสดุทุกพื้นผิว ตู้บิ้วอิน 5 ใบ (ตู้วางทีวี ตู้ครัวล่าง/แขวน ตู้เสื้อผ้า ตู้ใต้อ่าง) และเฟอร์นิเจอร์ เปิดดู 3D, Mood & Tone, BOQ และหน้านำเสนอได้ทันทีโดยไม่ต้องวาดเอง ไม่มีราคา (`src/interior/sample.ts`)

- **เครื่องมือ**: ผนัง ห้อง ประตู/หน้าต่าง วัด ภาพแปลน เหมือนโรงงาน แต่ไม่มีเสา พื้นที่ ทางเดิน และลูกศรงาน
- **คลัง**: ไม่มีแท็บ Mastrox เหลือ "เฟอร์นิเจอร์" (ชิ้นที่ใช้ในบ้านได้จากคลังอุปกรณ์) และ "ของฉัน"
- **ห้อง**: ประเภทเป็นห้องในบ้าน (นั่งเล่น ทานอาหาร ครัว นอน น้ำ ทำงาน แต่งตัว ซักล้าง ระเบียง โถง เก็บของ) ห้องที่วาดใหม่ชื่อ "ห้อง N" ประเภท "อื่น ๆ" จนกว่าจะเลือก (`src/interior/rooms.ts`)
- **วัสดุ**: เลือกห้องแล้วกำหนดวัสดุ พื้น / ผนัง / ฝ้า จากกริดรูป (~27 แบบ: ไม้ กระเบื้อง หิน ปูน อิฐ พรม สีทา ฝ้า) ผนังแต่ละหน้าใช้วัสดุผนังของห้องฝั่งนั้น (ผนังระหว่างสองห้องจึงมีสองหน้าต่างกันใน 3D ด้านนอกของผนังนอกเป็นสีผนังปกติ) คลิกผนังเดี่ยวเพื่อให้ผนังนั้นต่างจากห้อง แล้วเลือกได้ว่าใช้กับ **ทั้งสองหน้า** หรือเฉพาะ **ฝั่ง<ชื่อห้อง>** (`Wall.finishSide`) หน้าที่เหลือใช้วัสดุของห้องฝั่งนั้น Mood & Tone และ BOQ นับตามหน้าเดียวกับที่เห็นใน 3D หรือ **อัปโหลดรูปวัสดุเอง** (ย่อเป็น WebP เก็บใน IndexedDB ติดไปกับไฟล์ส่งออกและลิงก์แชร์ ตั้งความกว้างจริงของรูป 1 ช่วงได้) แปลน 2D ระบายพื้นด้วยสีหลักของวัสดุ 3D ปูลายจริงตามขนาดจริง (กระเบื้อง 60 ซม. ก็เห็นเป็น 60 ซม.) ภาพลายทั้งหมดวาดด้วยโค้ดใน `scripts/materials.mjs` (`node scripts/materials.mjs` สร้าง `public/materials/*.png` ใหม่) ไม่มีภาพถ่ายจากที่อื่น
- **3D**: เปิดมามองลงจากมุมสูงพอให้เห็นทั้งแปลนและพื้นข้ามผนังด้านหน้า (`src/view3d/frameInterior.ts`) ห้องมีฝ้าที่ความสูงฝ้า แต่เปิด 3D มาฝ้าซ่อนอยู่ เพราะกล้องเริ่มจากด้านบนและฝ้าจะบังทั้งห้อง ปุ่มฝ้าบนแถบมุมมองใส่ฝ้ากลับ ผนังเต็มความสูงเป็นค่าเริ่มต้น (สวิตช์ผนังเตี้ยแยกจากของโรงงาน) ผนังที่มีวัสดุยังมีขอบบนสีเทาแบบผนังธรรมดา (วัสดุหยุดต่ำกว่ายอด 2 มม. แล้วปิดด้วยแผ่นบางสี `WALL_TOP`)
- **Mood & Tone**: ปุ่มบนแถบบน เปิดหน้าสรุป ชุดสี (hex ของวัสดุที่ใช้ ไม่ซ้ำ) วัสดุแต่ละชิ้นว่าใช้ห้องไหน พื้น/ผนัง/ฝ้า กี่ ม² (พื้นและฝ้าตามพื้นที่ห้อง ผนังตามความยาว × ความสูงฝ้า หักประตูหน้าต่าง) และเฟอร์นิเจอร์พร้อมจำนวนและขนาด บันทึกเป็น PNG หน้าเดียวได้ ไม่มีราคา
- **BOQ / ใบเสนอราคา**: ปุ่มข้าง Mood & Tone มีสองแท็บ **ถอดปริมาณ** คิดจากเรขาคณิตเดียวกับ Mood & Tone ต่อวัสดุ: ปริมาณสุทธิ % เผื่อ (แก้ได้) จำนวนซื้อ และวิธีคิด ห้องสี่เหลี่ยมนับแผ่นกระเบื้องเต็ม/ตัดจากการวางจริงจากมุมห้อง ห้องรูปทรงอื่นคิดจากพื้นที่ + % เผื่อตามลายปู หน่วยคิดตั้งต้นมีเฉพาะขนาดมาตรฐานจริง (กระเบื้อง/ฝ้าทีบาร์ 60×60, ซับเวย์ 7.5×15, ยิปซัม 120×240, สี 35 ม²/แกลลอน/ชั้น 2 ชั้น, พรมกว้าง 3.66 ม.; ที่มาใน `src/interior/materialUnits.ts`) วัสดุอื่นและที่อัปโหลดเองคิดเป็น ตร.ม. ใส่ขนาดแผ่น แผ่น/กล่อง ฯลฯ เองได้ในปุ่มวิธีคิด ติ๊กคิดบัวพื้นได้ (เส้นรอบห้องหักประตู) เฟอร์นิเจอร์ที่วางขึ้นเป็นบรรทัดชิ้นด้วย ตู้บิ้วอินคิดจากรายการแผ่นของแต่ละตู้ แยกตามชนิดและความหนาแผ่น (ตร.ม. หรือเป็นแผ่นเมื่อใส่ขนาดแผ่นในปุ่มวิธีคิด) พร้อมบรรทัดความยาวปิดขอบ **ใบเสนอราคา** ใส่ราคาต่อหน่วยซื้อและค่าแรงต่อหน่วยเอง (ไม่มีราคาตั้งต้นใด ๆ) บรรทัดที่ว่างแสดง "ยังไม่ใส่ราคา" และไม่นับในยอด VAT % ตั้งได้ ข้อมูลลูกค้ามาจากชื่อโปรเจกต์ ส่งออก CSV ได้ทั้งสองแท็บ และ **พิมพ์ / บันทึก PDF** เป็น A4 จากหน้าพิมพ์ของเบราว์เซอร์ ราคาเก็บกับโปรเจกต์ (`priceBook`, `boqOptions`) ไปกับไฟล์ส่งออก แต่ไม่ไปกับลิงก์แชร์ แก้แต่ละช่องแล้ว Ctrl+Z ย้อนได้ทีละช่อง โค้ด: `src/interior/boqSurfaces.ts` (ห้อง → ผิว) `src/interior/BoqPage.tsx` เครื่องคิดอยู่ใน `src/interior/boq/`
- **นำเสนอ**: ปุ่มข้าง BOQ (บนมือถืออยู่ในเมนูหลัก) เปิดหน้าพรีวิวแผ่น A3 แนวนอน ทำจากโปรเจกต์ล้วน ไม่มีราคาหรือข้อความที่แอปแต่งเอง: **ปก** (ชื่อโปรเจกต์ บริษัท/ผู้ติดต่อถ้ามี วันที่ ภาพ AI ล่าสุด ไม่มีก็ใช้มุมมอง 3D ตอนนั้น) **แปลนห้อง** (ภาพแปลนแบบเวกเตอร์ + ตารางห้องและ ม²) **Mood & Tone** (ชุดสี hex วัสดุพร้อมลาย ห้อง/ผิว/พื้นที่ ข้อมูลชุดเดียวกับหน้า Mood & Tone) **เฟอร์นิเจอร์และตู้บิ้วอิน** (ภาพย่อ จำนวน ก×ล×ส ตู้บอกชนิดแผ่นและความหนา) และ **ภาพห้อง** แผ่นละ 1–4 ภาพ (ภาพ AI ทุกภาพ และมุม 3D ที่กด **เพิ่มมุมนี้** เก็บกับโปรเจกต์ใน `shots` ลบได้ ไม่มีภาพก็ไม่มีแผ่นนี้) รายการยาวต่อแผ่นถัดไปเอง ติ๊กเลือกหมวดที่จะใส่ได้ ทุกแผ่นมีชื่อโปรเจกต์และเลขหน้า **พิมพ์ / บันทึก PDF** ใช้หน้าพิมพ์ของเบราว์เซอร์ หน้าละแผ่น A3 แนวนอนไม่มีขอบ ภาพ 3D ถ่ายที่ 2400 px โค้ด: `src/interior/present/` (`sheets.ts` เลือกว่าอะไรอยู่แผ่นไหน)
- **แบบก่อสร้าง**: ปุ่มไม้บรรทัดข้างนำเสนอ (จอแคบกว่า 1500 px และมือถืออยู่ในเมนูหลัก "แบบก่อสร้าง (A3)") เปิดชุดแบบ A3 แนวนอนแบบงานสถาปัตย์ สารบัญแผ่นด้านซ้าย แผ่นที่เลือกด้านขวา ซูมด้วยล้อเมาส์หรือปุ่ม ลากเพื่อเลื่อน ตอนนี้มี **ID-00-01 ปก** (ชื่อโครงการ ลูกค้า วันที่ สารบัญแผ่น) และ **ID-04-01 แปลนพร้อมมิติ** (ผนังตัดทึบ ประตูพร้อมวงเปิด หน้าต่าง เฟอร์นิเจอร์และตู้เป็นเส้นบาง ชื่อห้องพร้อม ตร.ม. แถวมิติช่องเปิด แนวผนัง และมิติรวมผิวนอก แนวกริด 1,2/A,B ที่ผนังนอก ตัวเลขทุกตัวมาจากเรขาคณิตจริง) มาตราส่วนเลือกเองจาก 1:20–1:100 ที่ใหญ่สุดที่ใส่พอดี ทุกแผ่นมีกรอบชื่อแบบด้านขวา ช่องที่โปรเจกต์ไม่มีข้อมูล (ที่ตั้ง ผู้ออกแบบ ผู้ตรวจ) เว้นว่าง **พิมพ์ / บันทึก PDF** หน้าละแผ่น A3 เต็มขนาด **ส่งออก DXF** บันทึกแปลนเป็น DXF R12 ขนาดจริงหน่วย มม. แยก layer (wall opening furniture cabinet dim text grid) เปิดใน AutoCAD ได้ ต่อด้วย **ID-09-xx รูปด้านผนังภายใน** ห้องละสองด้านต่อแผ่น (A, B แล้ว C, D เรียงตามเข็มนาฬิกาเริ่มจากด้านที่มองไปทางเหนือ) มาตราส่วน 1:25–1:30: ผนังที่ตัดสองข้างและแถบฝ้า ประตูพร้อมเส้นทิศบานเปิด หน้าต่างตามระดับ sill จริง ตู้บิ้วอินวาดจากชิ้นเดียวกับรายการแผ่น (บาน ลิ้นชัก ฐาน ท็อป ตู้แขวนที่ระดับจริง) เฟอร์นิเจอร์ที่ชิดผนังเป็นเส้นบาง ป้ายวัสดุผนัง พื้น ฝ้า และมิติแนวนอน/แนวตั้งจากโมเดล แต่ละแผ่นส่งออก DXF ได้ ห้องตัวอย่างคอนโดได้ชุดแบบ 9 แผ่น โค้ดและวิธีเพิ่มแผ่นใหม่: `src/drawings/README.md`
- **ตู้บิ้วอิน**: หมวดแรกในคลัง (ตู้ล่าง ตู้แขวน ตู้สูง ชั้นเปิด ตู้เสื้อผ้า) วางแบบเดียวกับของอื่น แต่ละใบเก็บ spec ของตัวเอง (`PlacedObject.cabinet`, `src/interior/cabinet/`) แผงขวาแก้ชนิด กว้าง/ลึก/สูง สูงจากพื้น (ตู้แขวนเริ่มที่ 1.45 ม.) จำนวนช่อง แต่ละช่องเป็นบานเปิดซ้าย/ขวา บานคู่ ลิ้นชัก (กี่ชั้น) หรือโล่ง ชั้นวาง ชนิดแผ่น (ปาร์ติเกิล MDF HMR ไม้อัด สัก สะเดา) และความหนา ฐาน ท็อป สีหรือวัสดุของหน้าบานและโครง (วัสดุมีลายใน 3D) ทุกช่องย้อนได้ด้วย Ctrl+Z ลึกขึ้นแล้วหลังตู้ยังชิดผนัง ส่วน **รายการแผ่น** (พับได้) บอกชิ้น ขนาดตัด จำนวน พื้นที่ต่อวัสดุ และความยาวปิดขอบ ไม่มีราคา บนแปลนเห็นเส้นแบ่งช่อง วงเปิดบาน และกรอบลิ้นชัก ตู้แขวนเป็นเส้นประ ใน 3D ปุ่ม **เปิดตู้** บนแถบมุมมองเปิดบานและดึงลิ้นชักทุกตู้
- **เฟอร์นิเจอร์บ้าน**: เตียง 3.5/5/6 ฟุต โซฟา 1–3 ที่นั่งและตัว L โต๊ะอาหาร โต๊ะกลาง โต๊ะทำงาน เก้าอี้ โต๊ะเครื่องแป้ง ชั้นวาง โคมไฟ ขนาดเริ่มต้นเป็นขนาดทั่วไป (เขียนที่มาไว้ใน `src/interior/catalog.ts`) ใน 3D เป็นรูปทรงจาก `furnitureShapes.ts` แทนกล่อง เฉพาะโปรเจกต์ตกแต่งภายใน
- **นำเข้าโมเดลจาก SketchUp**: แท็บ "ของฉัน" มีปุ่ม **นำเข้าโมเดล 3D** รับ .dae, .obj (เลือก .mtl และภาพพื้นผิวมาพร้อมกัน), .glb, .gltf อ่านขนาดจริงให้ ถ้าไฟล์ไม่บอกหน่วย (OBJ) จะเดาจากขนาดและให้เลือกหน่วยเองได้ ไฟล์ .skp ขึ้นวิธี Export จาก SketchUp ไฟล์เก็บใน IndexedDB เป็นของคลัง "ของฉัน" (ลบออกจากคลังแล้วไฟล์หายด้วย ลบหรือทำสำเนาโปรเจกต์ไม่แตะไฟล์) ติดไปกับไฟล์ส่งออกและลิงก์แชร์ของโปรเจกต์ที่วางมัน เกิน 5 MB จะเตือนว่าลิงก์จะหนัก บนแปลนเป็นกล่องตามขนาด ใน 3D เป็นโมเดลจริง ตัวอ่านไฟล์ของ three.js โหลดเมื่อใช้เท่านั้น โปรเจกต์โรงงานไม่เห็นโมเดลที่นำเข้า
- **ภาพ AI**: ปุ่ม **ภาพ AI** บนแถบบน (บนมือถืออยู่ในเมนูหลัก "สร้างภาพห้องด้วย Google Flow") เปิดไดอะล็อกเดียวกับของโรงงาน (หัวข้อ "ภาพ AI ด้วย Google Flow") แต่พรอมต์เขียนจากห้อง: แต่ละห้องบอกประเภท ขนาด พื้นที่ และความสูงฝ้า วัสดุพื้น ผนัง (ทีละผนัง: วัสดุเดียวทุกผนังเขียนครั้งเดียว ไม่งั้นบอกวัสดุพร้อมจำนวนผนังและความยาว) และฝ้า เป็นชื่ออังกฤษของวัสดุพร้อมรหัสสี (วัสดุที่อัปโหลดใช้ชื่อที่ผู้ใช้ตั้งกับสีเฉลี่ยของรูป) ประตูหน้าต่างพร้อมขนาด เฟอร์นิเจอร์แต่ละชิ้นพร้อม ก×ล×ส และตู้บิ้วอินพร้อมชนิด ช่อง หน้าบาน สีหน้าบานและโครง ผิวที่ไม่มีวัสดุไม่เขียนถึง และไม่ใส่สไตล์ แสง หรือของที่ไม่มีในโปรเจกต์ ภาพที่ได้กลับมาเก็บใน `renders` เหมือนของโรงงาน และหน้านำเสนอใช้เป็นภาพปกและแผ่นภาพห้องเอง โค้ด: `src/interior/renderPrompt.ts` (ชื่ออังกฤษของวัสดุอยู่ใน `materials.ts` ของเฟอร์นิเจอร์ใน `catalog.ts`)
- **หุ่นคน**: หมวด "คน" ในแท็บเฟอร์นิเจอร์ (ผู้ชาย 1.75 ม. ผู้หญิง 1.62 ม. เด็ก 1.20 ม. ไม่มีพนักงานโรงงาน) ไว้ดูสัดส่วนห้องและเฟอร์นิเจอร์ ห้องตัวอย่างคอนโดมีผู้ชายยืนในห้องนั่งเล่น ทำงานเหมือนหุ่นของโรงงาน (หัวข้อ "มุมมอง 3D") แต่ **ท่าขยับเปิดเป็นค่าเริ่มต้น** และจำแยกจากของโรงงาน หุ่นไม่ใช่เฟอร์นิเจอร์: ไม่อยู่ใน Mood & Tone, BOQ, แผ่นเฟอร์นิเจอร์ของหน้านำเสนอ, พรอมต์ภาพ AI, แบบก่อสร้าง และจำนวนเฟอร์นิเจอร์ในแผงขวา
- ลิงก์แชร์และแถบของลูกค้าพูดถึงการย้ายเฟอร์นิเจอร์แทนเครื่อง

## ภาพ AI ด้วย Google Flow

ปุ่ม **ภาพ AI** บนแถบบน (หรือเมนูหลัก) เปิดไดอะล็อกสำหรับทำภาพโรงงานสมจริงด้วย [Google Flow](https://labs.google/fx/tools/flow) Flow ไม่มี API และไม่มีลิงก์ที่ส่งพรอมต์ไปได้ จึงเป็นการส่งต่อ 3 ขั้น:

1. **พรอมต์**: เขียนให้เองจากแปลน (ขนาดอาคาร ห้องกับโซน เครื่องแต่ละรุ่นพร้อมจำนวนและขนาด อุปกรณ์ ประตู; โปรเจกต์ตกแต่งภายในเขียนจากห้อง วัสดุ และเฟอร์นิเจอร์แทน) เป็นภาษาอังกฤษ แก้ได้ตามใจ ที่แก้ไว้บันทึกกับโปรเจกต์ ปุ่ม "เขียนใหม่จากแปลน" ทิ้งที่แก้แล้วสร้างใหม่ตามแปลนปัจจุบัน
2. **ภาพอ้างอิง**: ถ่ายจากมุมมอง 3D ที่เปิดอยู่ (ไม่มีก็ใช้แปลน 2D) ดาวน์โหลดไปอัปโหลดใน Flow ให้ตำแหน่งเครื่องตรงกับแปลน
3. **ภาพที่ได้กลับมา**: ลากไฟล์มาวาง กด Ctrl+V หรือเลือกไฟล์ ภาพเก็บใน IndexedDB ข้างภาพแปลน ไปกับไฟล์ส่งออกและลิงก์แชร์ (ย่อเป็น WebP) ดาวน์โหลดหรือลบได้จากแกลเลอรีในไดอะล็อก

ปุ่ม "คัดลอกพรอมต์แล้วเปิด Google Flow" เปิด Flow ในแท็บใหม่และคัดลอกพรอมต์ให้พร้อมวาง โค้ดอยู่ที่ `src/model/renderPrompt.ts` (พรอมต์โรงงาน ข้อความถูกตรึงไว้ด้วย snapshot ใน `renderPrompt.test.ts`), `src/interior/renderPrompt.ts` (พรอมต์ห้อง) และ `src/ui/FlowDialog.tsx` (เลือกพรอมต์ตาม `project.kind`)

## แชร์ลิงก์ให้ลูกค้า

ปุ่ม **แชร์ลิงก์** บนแถบบน (หรือเมนูหลัก) เก็บสำเนาของแปลน ณ ตอนนั้นไว้บนเซิร์ฟเวอร์ แล้วให้ลิงก์ `#/s/<รหัส>` ไปส่งให้ลูกค้าทางไหนก็ได้ ใส่ข้อความถึงผู้รับได้ (ผู้รับกดปิดแถบข้อความได้)

ลูกค้าเปิดลิงก์ในเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งหรือสมัครอะไร และเห็นแปลนใน **โหมดลูกค้า**: ลากย้ายเครื่อง หมุน ลบ หรือเพิ่มจากคลังได้ ดู 3D ได้ แต่ผนัง ห้อง ประตู เสา และภาพแปลนคงเดิม (เครื่องมือวาดและเลเยอร์ไม่แสดง) การย้ายบันทึกในเบราว์เซอร์ของลูกค้า เปิดลิงก์เดิมซ้ำก็เห็นที่ย้ายไว้ (ลิงก์หนึ่งมีสำเนาเดียวต่อเบราว์เซอร์ จำไว้ที่ `factory:share:<รหัส>` เปิดซ้ำหรือเปิดพร้อมกันสองครั้งก็ไม่เพิ่มสำเนา ลบสำเนาออกจากรายการแล้วเปิดลิงก์ใหม่จึงนำเข้าใหม่) เมื่อพอใจกด **ส่งกลับ** เพื่อได้ลิงก์ใหม่ของการจัดวางนั้นส่งคืนผู้ขาย ซึ่งเปิดดูได้แบบเดียวกัน และเปิดในโหมดแก้ไขเต็มได้จากเมนูหลัก (ลิงก์ที่เปิดกลายเป็นโปรเจกต์ใหม่ในรายการ)

ลิงก์ส่งเฉพาะที่ลูกค้าต้องใช้: ภาพแปลนถูกย่อเป็น WebP และไม่ส่งเส้นเวกเตอร์ของ PDF (ใช้แค่ตอนวาดผนังทับ) แปลนจาก CAD จึงเล็กลงราว 4 เท่า ลิงก์เป็นสำเนา: แก้โปรเจกต์ต่อหลังแชร์ไม่กระทบลิงก์ที่ส่งไปแล้ว ขนาดที่ส่งเป็นลิงก์ได้ไม่เกินราว 5 MB (ภาพแปลนและโมเดลที่อัปโหลดนับรวม) เกินนั้นให้ส่งออกเป็นไฟล์แทน

ฝั่งเซิร์ฟเวอร์คือ `src/server/share.ts` (`POST /api/share` เก็บ, `GET /api/share/:id` อ่าน, ส่งเป็นชิ้น gzip ผ่าน `/api/share-part`) รันบน Cloudflare Worker ผ่าน `worker/index.ts` และเก็บลง Cloudflare KV ตอนพัฒนา `npm run dev` และ `vite preview` มี API เดียวกันจากปลั๊กอินใน `vite.config.ts` เก็บเป็นไฟล์ใน `.share-dev/` (ไม่เข้า git)

## นำเข้าแปลนที่มีอยู่

อัปโหลดรูปหรือ PDF ของ layout เป็นพื้นหลังได้ตลอด (เมนู "อัปโหลดแปลน" ในแปลน 2D) จากนั้นเลือกได้ว่าจะ

- **วาดห้องทับแปลน** (แนะนำ): ลากกรอบทับห้องทีละห้องเป็นพื้นที่โปร่งแสง มุมดูดเข้าหาเส้นในรูปเอง
- **สร้างผนังอัตโนมัติ**: ให้แอปอ่านผนัง ประตู หน้าต่าง เสา และชื่อห้องจากแปลน (เฉพาะตัวอาคาร) แก้ต่อหรือเลิกทำได้
- **ใส่เฟอร์นิเจอร์จากแปลน** (เฉพาะ PDF จาก CAD): ปุ่มแยก ใส่เครื่องจักร โต๊ะ เก้าอี้ ห้องน้ำ บันได ที่วาดไว้ในแปลนลงในห้องที่มีอยู่ กดซ้ำจะแทนชุดเดิม ไม่ซ้อน ของที่วางเองไม่ถูกแตะ

PDF ที่เป็นเวกเตอร์จาก CAD อ่านได้ตรงที่สุด รูปถ่ายหรือสแกนจะขอให้วัดสเกลก่อน (คลิก 2 จุดแล้วใส่ระยะจริง) ปรับความเข้มของภาพพื้นหลังหรือซ่อนได้จากเมนูเดียวกัน

## มุมมอง 3D

สลับ 2D / 3D จากสวิตช์บนแถบบน ปุ่มเล็กข้างสวิตช์คือแบ่งจอ (2D กับ 3D ข้างกัน มีบนจอกว้างเท่านั้น) ภาพ 3D เป็นแบบเรียบ: ห้องตามสีโซน ผนัง ประตู เสา อุปกรณ์เป็นรูปทรงง่าย ๆ
และ **เครื่อง Mastrox เป็นก้อน**: `src/machines/blocky.js` (คัดลอกจากโปรเจกต์ Model) แปลงโมเดลจริงเป็นกล่องสีเดิม ตัดชิ้นเล็กทิ้ง และแปะโลโก้ mastrox ไว้ตรงที่เครื่องจริงมี
จึงเห็นโครง สัดส่วน และฝาส้มของแต่ละรุ่นโดยไม่มีรายละเอียดที่ดูไม่เหมือน ระดับเลือกได้ที่ `LEVEL` ใน `src/view3d/machines3d.ts`
(`chunky` ก้อนใหญ่ไม่กี่ก้อน รวมก้อนสีเดียวกันที่ติดกัน ค่าปัจจุบัน · `blocky` ทุกชิ้นเกิน 12 ซม. เป็นกล่อง · `box` กล่องเทาก้อนเดียว) เทียบทุกระดับได้ที่ `compare.html` ในโปรเจกต์ Model
ชื่อรุ่นลอยอยู่เหนือเครื่อง คลิกเพื่อดูรูปเครื่องจริงในแผงรายละเอียด
ปุ่มมุมขวาบนของ 3D:

- **ผนังเตี้ย** ตัดผนังลงเกือบติดพื้นให้เห็นห้องและประตูชัด (เปิดไว้เป็นค่าเริ่มต้น)
- **ย้ายเครื่อง** ปุ่มสีน้ำเงินบนสุดของแถบมุมขวา (สีต่างจากปุ่มมุมมองอื่น) สลับเป็นโหมดลากเครื่องบนพื้นได้เลย (ดูดเข้าหาผนังและเครื่องข้างเคียงเหมือนบนแปลน กด R หรือปุ่มหมุน ลากพื้นว่างยังหมุนมุมมองได้) เริ่มปิดไว้เสมอ และคลิกเครื่องในคลังขณะอยู่หน้า 3D จะวางเครื่องนั้นกลางจอให้ลากต่อได้ทันที หรือลากการ์ดจากคลังไปปล่อยบนพื้น 3D ตรงที่ต้องการก็ได้ (ระหว่างลากเห็นรูปร่างเครื่องโปร่งใสตามเมาส์บนพื้น ไม่ใช่รูปถ่าย)
- **มุมมองจากด้านบน**, **มุมมองทั้งโรงงาน**, **บันทึกรูปมุมมองนี้** (PNG)
- **คน** และ **ท่าขยับ** ขึ้นเฉพาะเมื่อมีหุ่นคนในโปรเจกต์ (ดูด้านล่าง)

**หุ่นคนเทียบขนาด**: หมวด "คน" ในแท็บอุปกรณ์ของคลังมี ผู้ชาย 1.75 ม. ผู้หญิง 1.62 ม. เด็ก 1.20 ม. และ **พนักงาน** 1.75 ม. (ชุดเรียบ หมวกนิรภัยสีส้ม) วางและหมุนแบบเดียวกับของอื่น ด้านหน้าคือด้านที่หุ่นหันไป ไว้ให้ลูกค้าเห็นว่าเครื่องสูงใหญ่แค่ไหนเมื่อมีคนยืนข้าง ๆ โรงงานตัวอย่างมีพนักงานยืนหน้า Rakete 3500A และ Nebula บนแปลนเป็นสัญลักษณ์คนมองจากบน (วงรีไหล่ วงกลมหัว จมูกชี้ทางที่หัน) ไม่ใช่กล่อง และ **ไม่นับเป็นสิ่งกีดขวาง** ในปัญหาการวาง (ยืนทับเครื่องหรือที่ยืนทำงานก็ไม่ขึ้นป้ายแดง) ไม่อยู่ในพรอมต์ภาพ AI แบบก่อสร้าง และรูปด้านผนัง ใน 3D ผู้หญิง เด็ก และพนักงานเป็นหุ่น low-poly ที่สร้างด้วยโค้ด (`src/view3d/figures3d.ts` สัดส่วนหัวราว 1/7.5 ของความสูง เด็ก 1/6) ส่วน **ผู้ชายเป็นโมเดล 3D** "Business Man - Low Polygon game character" โดย [manoeldarochadeoliveira](https://sketchfab.com/manoeldarochadeoliveira) จาก [Sketchfab](https://sketchfab.com/3d-models/business-man-low-polygon-game-character-b6f6740f883b4749abac47af0045a9dd) สัญญาอนุญาต [CC BY 4.0](http://creativecommons.org/licenses/by/4.0/) (ต้องให้เครดิตผู้สร้าง: อยู่ในคำอธิบายของการ์ดในคลังและในไฟล์โมเดล) ปรับให้สูงตามที่ตั้งโดยไม่ยืดกว้าง/ลึก และใช้ท่า idle ของโมเดลเอง ไฟล์ `public/models/business-man.glb` (~0.9 MB) ทำจากไฟล์ที่ดาวน์โหลดด้วย `node scripts/figure-model.mjs <ไฟล์ .glb>` (เก็บแค่ท่า idle ย่อพื้นผิวเป็น JPEG 1024/512 px จาก 6.3 MB) โหลดครั้งแรกที่มีผู้ชายในฉาก ระหว่างนั้นหรือถ้าโหลดไม่ได้จะเห็นหุ่นแบบโค้ดแทน ปุ่ม **คน** บนแถบ 3D ซ่อน/แสดงหุ่นทั้งหมดทั้งแปลนและ 3D (หุ่นยังอยู่ในโปรเจกต์ วางหุ่นใหม่แล้วแสดงกลับเอง) ปุ่ม **ท่าขยับ** ให้หุ่นหายใจ ถ่ายน้ำหนัก แกว่งแขน หันหัวเล็กน้อย (หุ่นแบบโค้ดคาบ 4–6 วินาที ผู้ชายใช้ท่า idle 8 วินาทีของโมเดล แต่ละตัวไม่พร้อมกัน เท้าอยู่กับที่) **โรงงานปิดเป็นค่าเริ่มต้น** ภาพ 3D ของโรงงานจึงนิ่งเหมือนเดิม ท่าขยับวาดราว 30 ภาพต่อวินาทีเฉพาะตอนเปิด และหยุดเองเมื่อแท็บถูกซ่อนหรือเปิดหน้า BOQ/นำเสนอ/แบบก่อสร้างทับ ไม่มีหุ่นก็ไม่วาดอะไรเพิ่ม ทั้งสองปุ่มจำไว้ในเบราว์เซอร์ (`figures.view` ใน localStorage) ความสูงและที่มาอยู่ใน `src/model/figures.ts`

### ขนาดเครื่อง Mastrox

ขนาดฐานของแต่ละรุ่น (และของ Rakete 3500A กับอุปกรณ์เสริมทุกชุด) อยู่ใน `src/machines/sizes.json` วัดจากโมเดล 3D ใน `src/machines/`
ซึ่งคัดลอกมาจาก `D:Job DewModelmastrox-models` (แอปใช้วัดขนาดและทำก้อน ไม่วาดรายละเอียด) ถ้าแก้โมเดลในโปรเจกต์นั้น ให้คัดลอก `machines/blocky.js` และ
`machines/*.js` มาทับ (รูปเครื่องจริงใน `photos/` ย่อลง `public/photos/*.webp` ด้วย `node scripts/photos.mjs` และเพิ่มรุ่นใหม่ใน `src/model/photos.ts`)
แล้วใส่ส่วนที่แก้เฉพาะในนี้กลับ: `lib.js` เขียน URL ของภาพโลโก้เต็มชื่อไฟล์ (ไม่งั้นภาพหายตอน build) · `registry.js` กับ `rakete-real.js` รับตัวเลือกเสริมต่อเครื่อง (และ `rakete-real.js` วางตู้คอนโทรลขนานข้างหลังเครื่อง ห่าง 30 ซม. ส่วน `blocky.js` แปะโลโก้บนก้อนที่อยู่ใต้โลโก้จริง ไม่ใช่ก้อนหน้าสุด) และ `data.js` คือ `data/machines.js` บวกบล็อก `options`
ของ Rakete 3500A จากนั้นรัน `npm run sizes` เพื่ออัปเดตขนาด

เทสต์อยู่ข้างโค้ดที่มันตรวจ (`*.test.ts`) ครอบคลุมเวกเตอร์ ผัง/ห้อง weld snap พื้นที่ ประตู และการตรวจระยะวาง ส่วน `e2e/` เป็น Playwright smoke test: เปิดโรงงานตัวอย่าง วาดห้อง วางเครื่อง เลิกทำ วัดระยะ ส่งออกรูป เปิด 3D เพิ่มโมเดลในคลังของฉัน และเปลี่ยนชื่อ รันบน GitHub Actions ทุก push ด้วย

## ขนาดไฟล์ที่โหลด

three.js และโมเดลเครื่อง Mastrox แยกเป็น chunk ของตัวเอง (`three`, `models`) โมเดลโหลดเมื่อเปิดมุมมอง 3D ครั้งแรกเท่านั้น (คลังใช้รูปถ่าย) หน้ารายการโปรเจกต์และแปลน 2D ไม่โหลดสองก้อนนี้ โมเดลผู้ชาย (`public/models/business-man.glb` ~0.9 MB) โหลดเฉพาะเมื่อมีหุ่นผู้ชายใน 3D หรือในรูปคลัง

## การเผยแพร่

เว็บอยู่บน **Cloudflare Workers** (ชื่อโปรเจกต์ `factory-plan-design`) ต่อกับ GitHub repo นี้ build จาก `main` ทุก push หน้าเว็บคือไฟล์ใน `dist/` ส่วน `/api/*` (ลิงก์แชร์) คือ `worker/index.ts` ตั้งไว้ใน `wrangler.jsonc` workflow GitHub Pages มีไว้รันด้วยมือเท่านั้น

**สาขา:** งานประจำวันทำและ push ที่ `dev` ซึ่งไม่ขึ้นเว็บจริง พอพร้อมปล่อยค่อย merge `dev` เข้า `main` หนึ่งครั้ง เว็บจริงจะ build ตอนนั้น

ตั้งค่าใน Cloudflare (Workers & Pages → Create → Import a repository):

- Project name `factory-plan-design` (ต้องตรงกับ `name` ใน `wrangler.jsonc`)
- Build command `npm run build` · Deploy command `npx wrangler deploy` · Preview command `npx wrangler versions upload`

ลิงก์แชร์ต้องมีที่เก็บ KV หนึ่งก้อน: สร้างใน **Storage & Databases → KV → Create** แล้วเอา **Namespace ID** มาใส่ใน `wrangler.jsonc`
เป็น `"kv_namespaces": [{ "binding": "SHARES", "id": "<ID>" }]` แล้ว push ก่อนใส่ หน้าเว็บใช้ได้ แต่กดแชร์จะขึ้นว่า
"เซิร์ฟเวอร์ยังไม่ได้ตั้งที่เก็บลิงก์ (KV binding SHARES)" (อย่าใส่ binding ผ่านหน้า dashboard อย่างเดียว เพราะ deploy ครั้งถัดไปจะเอาตาม `wrangler.jsonc`)
KV แบบฟรีเขียนได้ 1,000 ครั้งต่อวัน (แชร์หนึ่งครั้งใช้ราว 2–3 ครั้ง) และเก็บได้ 1 GB

ทดสอบแบบ Cloudflare ในเครื่อง: `npm run build` แล้ว `npx wrangler dev`
